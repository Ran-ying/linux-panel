# V2Ray 本机管理

## 实际目标环境（2026-10-17，只读检测）

- VPS：Ubuntu 24.04.3 / amd64，V2Fly **V2Ray 5.47.0**。
- Binary: /usr/local/bin/v2ray，systemd: v2ray.service（active、enabled）。
- 主配置：/usr/local/etc/v2ray/config.json，root-owned；支持 V2Ray 5.x 常见字段和保留旧的 inboundDetour/outboundDetour。
- 读取主配置时不向 Issues、测试日志或仓库输出真实地址、UUID、密码和私钥。
- Ubuntu 24.04 apt 的候选版本为 4.34.0，因此安装入口不使用 apt 的旧版本。

## 页面布局

- 侧边栏继续只有一个 V2Ray 模块，其 ActionCard 外壳为透明无框（`chrome:'flat'`）；最上方保留四张独立圆角状态卡片，依次显示内核、服务、开机启动和入站/出站数量（桌面四列、手机两列）。
- **服务卡片**内直接放「启动、停止、重启」，**开机启动卡片**内放「关闭开机自启 / 启用开机自启」；不再单独显示服务按钮工具栏。服务操作仍须二次确认。
- 状态卡片下方的独立一行左侧是配置文件路径，**最右侧**是「刷新状态与配置」按钮。
- 左侧配置目录**仅显示根 JSON 中已配置的已知字段**，完整内容（JSON 根对象）固定在最前并与字段项留出额外间距。「添加字段」是独立按钮，位于左侧列表上方；点击打开独立弹窗，下拉选择当前缺失的支持字段，取消不改动；确认后仅往本地草稿明确添加对应字段（inbounds/outbounds 和旧版 detour 为 `[]`，routing 为 `{rules:[]}`，其他部分为 `{}`），自动切换相应编辑页面。原本缺失的字段不因浏览其他配置而自动创建，完整 JSON 编辑删除字段后导航会自动隐藏它。
- 保存版本冲突来自 V2Ray root Action 的 SHA-256 字节级检查：服务器配置与本页上次读取的版本不同时返回 HTTP 409 并拒绝覆盖；不意味着一定有人在其他程序修改，也可能是面板另一页/上一次成功保存后页面未完成刷新。修复前端在成功保存后**立即接收服务端新 revision**，先重新读取，再尝试刷新状态摘要，即使状态查询临时失败也不丢失版本同步。真正的 409 仍禁止覆盖，保留本地草稿并说明需备份/核对最新配置；不做静默重试或无条件覆盖。
- 下方编辑区不再有「能力概览」、横向页签或单项下拉框。使用**左侧竖向配置目录 + 右侧 JSON 编辑区**，目录第一项是「完整内容」，其后依次是入站、出站、路由、DNS、传输、日志、策略、API、统计等配置部分及旧版字段。校验/保存/放弃按钮排列在右侧编辑器下方。
- 「校验配置」「保存并应用」「放弃修改并重新读取」移到**编辑器顶部**，工具栏右侧增加「可视化 / JSON」切换。完整内容及其它未实现可视化的分类继续使用 JSON；入站、出站、路由和旧版入站/出站支持可视化。
- 入站/出站可视化编辑标签、协议、地址、端口和常用传输参数，展示已有客户端、服务器及用户字段，支持增删条目；**现代与旧版入站、出站四种列表完全分开**：左侧「入站连接（inbounds）」仅展示和编辑 `inbounds`，「出站连接（outbounds）」仅展示和编辑 `outbounds`；仅当原始/本地候选 JSON **实际含有** `inboundDetour` 或 `outboundDetour` 属性时，各自在左侧显示「旧版入站扩展（inboundDetour）」或「旧版出站扩展（outboundDetour）」独立条目，编辑原来的数组，不混入现代连接。旧版字段缺失不生成入口，也不自动创建、转换、迁移或删除；已有值为 `null` 或非数组时保留独立入口，以 JSON 模式准确显示原始值，不当成空数组，也不让可视化编辑触碰它。路由可视化同时支持 routing.rules 和旧版 routing.settings.rules，编辑规则标签、域名/IP/端口等条件。「IP 条件」仅在有实际数据或被用户通过「添加条件」显式展开时显示，始终位于规则表单最后，横跨全部列，输入宽度为 100%，并随换行内容动态增高（无需 textarea 内部滚动）；字段值仍为 JSON 字符串数组。类型、入站标签和出站标签三个基础字段标签与输入控件字号/高度统一为顶端对齐，入站标签即使包含多行也不拉低其它字段；「选择条件」「添加条件」固定在规则表单的最下面，两项高度同为 38px。新增规则仅初始化 `type:'field'`、`inboundTag:[]` 和 `outboundTag:''`，其余可选字段不自动创建；通过条件下拉菜单从「平衡器标签、端口条件、网络条件、来源 IP、域名条件、协议条件、IP 条件」选择，再点击「添加条件」展开。现有非空可选条件自动显示，空字符串/空数组/仅空白文本默认隐藏但不删除原 JSON 键；仅点击「添加条件」不会更改 JSON，实际输入才修改本地草稿。规则标题右侧在「移除」前有「重命名」按钮，打开独立的 `tag` 编辑弹窗。无 `tag` 时输入框为空（不能从 `outboundTag` 补值）；确认才写回本地草稿的 `tag` 字段，清空则删除 `tag` 并恢复标题按 `outboundTag` 显示；取消不修改，不触发服务端 Save。路由规则每个有对应 JSON 属性的中文字段名及「添加条件」下拉选项后，都显示括号内原始字段名（如「类型（type）」「入站标签（inboundTag）」「目标出站标签（outboundTag）」「IP 条件（ip）」），便于在可视化与 JSON 之间对应。路由规则的**目标出站标签**使用下拉框，从当前未保存草稿的 outbounds/outboundDetour 的 tag 读取；**入站标签**是可包含多个值的列表，每个值单独使用下拉框并支持增删，从 inbounds/inboundDetour 读取。未找到对应连接的历史/自定义 tag 仍作为当前选项显示，选择前不修改 JSON，避免遗失旧路由。
- **V2Ray 配置编辑器全部有对应原始键的中文名称都标注 JSON 属性**：左侧竖向导航显示 `入站连接（inbounds）`、`出站连接（outbounds）`、`路由规则（routing）`、`DNS（dns）`、`API（api）` 等全部真实顶层属性；「完整内容（JSON 根对象）」没有虚构的原始键。右侧路由及入站/出站、旧版连接、客户端/服务器/用户及各级可视化嵌套字段、分组标题也标记实际键或路径（`streamSettings.network`、`settings.clients`、`settings.vnext` 等）。字段标题统一 **600 粗体**；输入框、下拉框、文本域、重命名弹窗值均为 **400 常规字重**，避免继承标题字重；路由三个基本字段和移动端对齐保持不变。
- 可视化模式的 **协议、监听地址、传输网络、传输安全**均为下拉框，覆盖 V2Fly 常见值，并将配置中已存在的自定义/历史值作为一项保留；不操作下拉框不会改写源 JSON。客户端 ID 和服务器用户 ID 用普通可见文本输入框，密码仍使用遮蔽输入。
- 页面所有原生单选框统一使用明/暗色适配的下拉箭头，箭头距右边框 14px（与常用控件上下留白接近），并为选项文字保留 34px 右内边距，包括设置、任务筛选、文件弹窗及 V2Ray 编辑器；不向多选列表强制添加装饰。\n- 向下滚动时，左侧竖向配置列表与编辑器顶部操作栏（校验/保存/放弃修改/可视化/JSON）均采用 `position:sticky` 保持在可视范围内，左侧长列表内部可滚动。手机端根据面板实际测量的固定顶部信息栏高度设置吸附位置。移除可视化配置区多余的说明文字。
- 可视化编辑始终只影响浏览器内候选配置。复杂协议专用及未显示字段依然通过 JSON 模式编辑并原样保留；切换视图不会上传配置。只有用户点击「保存并应用」才使用原有 SHA revision、内核 test -c 校验与重启失败回滚。
- 分类切换前将有效的当前编辑写回本地候选 JSON；遇到非法 JSON 时阻止离开当前分类并展示错误。未编辑的缺失分类不自动生成空对象。保留未知字段、服务端 SHA 版本冲突检测、核心配置校验、失败回滚。未安装时不显示服务卡片操作，只提供受确认的安装入口。


## 模块功能

- 状态摘要：内核版本、二进制路径、服务运行及自启状态、入站/出站数量、已配置的功能字段。
- 认证 Web 的完整 JSON 和分项 JSON 编辑：入站、出站、路由、DNS、传输、日志、策略、API、统计、反向代理、监测及旧字段。**不丢弃未知字段**，不自动从 V2Ray 转换到 Xray。
- 配置检测：使用当前 V2Ray 内核的 test -c 命令对候选临时文件检查，不切换工作配置。
- 保存：SHA-256 revision 防覆盖、严格 JSON、原子替换并保留权限；失败拒绝修改。对正在运行的服务尝试重启；重启失败则恢复之前的配置并尝试重新启动旧服务。原本停止的服务不自动启动。
- 系统服务：启动、停止、重启、设置/取消开机自启，Web 有确认弹窗。
- **未安装入口**：仅 Linux amd64、无程序/同名配置/service 时显示安装；固定官方 V2Fly v5.47.0 release ZIP（sha256 56215328ad7a65e387e772af22232ac6531c34a1bb2252a64599a3a41aa7de5c），仅提取 v2ray、geoip.dat 和 geosite.dat；创建服务及默认仅监听 127.0.0.1:10808 的 SOCKS 配置。**不自动下载或覆盖现有安装。**

## 权限与限制

- 对应 v2ray.status/read/test/save/service/install 六个 Action，其中仅不含敏感信息的 status 允许 MCP；读取认证配置仅在 Web 管理员认证/CSRF 后通过独立 root Handler 执行。
- 仅作用于固定官方布局 /usr/local/etc/v2ray/config.json（后备 Ubuntu 发行版布局 /etc/v2ray/config.json）和固定 v2ray.service；不接受任意文件路径、任意命令、安装 URL 或服务名。
- 独立 root Handler 通过 package-manifest 固定部署；已完成一次性受控 root 包自动更新迁移的服务器，普通签名主分支更新会同步源码；未启用 root 执行器的首次安装需要按 PRIVILEGED.md 激活。
- 不修改正在运行的实际 VPS 配置、流量路由、证书或端口。安装只在管理员点击并确认后执行，且需要 GitHub 网络、unzip、systemctl 与 root。
- API/stats/transport 字段可通过 JSON 编辑，但首版**未实现** V2Ray gRPC API 的运行时用户增删、流量统计实时查询、连接详情、订阅转换、自动版本升级、多实例或非标准 confdir 接管。
- 编辑配置时可能使代理断联；保存前有内核检查及失败恢复，但不能保证跨外部网络或上游服务的连通性。敏感配置不得记录在日志。
- 用户自行配置开放公网监听、TLS 等；默认安装仅建立回环入站，避免无意开放代理。

## 维护方式

- 根操作代码：platform/privileged/v2ray-contracts.js、v2ray-operations.js，固定注册于 handlers.js 及 package-manifest.json。
- 业务模块：modules/v2ray/manifest.json、index.js、ui/presentations.js。
- 面板通用 renderer：V2RayManager.vue，通过 ActionCard 和严格 presentation descriptor 连接。
- 自动测试：tests/v2ray.test.js 使用临时目录、模拟服务运行器验证保留旧字段、配置版本冲突、校验拒绝及重启失败回滚；浏览器测试覆盖不同视口、未安装入口和编辑操作。
- 不在真实 VPS 上执行测试安装或触碰真实 V2Ray 用户配置。
