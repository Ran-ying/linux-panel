# Linux Panel v0.3 安全边界

**本里程碑实现了基础认证、服务端授权和审计，但未完成独立公网安全评审。不要直接将其作为公开管理面板部署。**

## 已实现

- 无公开注册和默认密码。初始管理员只能在服务器本地通过 `npm run admin:init` 创建，终端隐藏输入密码。
- 密码：Node.js `crypto.scrypt` (N=32768,r=8,p=1) + 随机盐，密码哈希在私有文件中。
- 会话：高熵随机 Token，服务端只存 Token SHA-256 摘要；12 小时固定过期；HttpOnly、SameSite=Strict，生产 HTTPS 下设置 Secure。
- 登录保护：要求自定义 Web 请求头，检查存在的 Origin；按访问来源暂存失败计数（单进程、有限次尝试）。
- 对除了状态和登录之外的所有 `/api/*` 要求有效会话。所有 POST、PUT、PATCH、DELETE 等请求必须携带会话关联的 CSRF Token。
- Action 的 `permission` 由服务端检查，目前唯一管理员角色拥有全部权限；前端对 Action 的发现和执行无法绕过此检查。
- 账户管理：修改密码撤销全部会话，可单独撤销登录会话；持久化审计记录登录、执行 Action、修改设置等事件元数据，不保存密码和业务结果。
- 私有文件：0600 原子写入，状态目录默认为仓库下已忽略的 `data/`，建议正式使用私有专用路径；不要运行多个面板进程共用同一 JSON 文件。
- 服务端继续绑定 `127.0.0.1`，没有新增任意 Shell 或文件修改 Action。

## 尚未完成 / 公开部署前必须处理

1. 独立安全审计和端到端浏览器测试；身份验证及授权的单元测试**不等于**公开环境安全验收。
2. 受支持且持续更新的 Linux 操作系统；现有 CentOS 7 已过维护期，不建议作为公网面板宿主。
3. HTTPS、完整的 CSP/静态安全头、Nginx 请求体和速率限制、可信代理/IP 处理、登录失败后的防锁定和滥用缓解。当前 Fastify `trustProxy:false`，经 Nginx 转发时看到的通常是代理 IP，不能把应用内 IP 限流当作可靠的公网防护。
4. 会话及状态文件安全加固：部署账号隔离、备份、磁盘满处理、锁定单实例、密钥/凭据轮换与故障恢复。原子 JSON 文件方案定位为单进程原型存储。
5. 安全的 OAuth 授权服务器、Access Token 生命周期与撤销、MCP 扩展单独审核，留给 v0.4。
6. RBAC 多用户、2FA、登录设备详细审计、长期日志存储、防篡改等未来功能。
7. 只读 Action 是可信代码约定，并非真实沙箱，MCP 或第三方模块不可由不可信用户直接安装。

**重要**：`PANEL_PUBLIC_ORIGIN` 校验用于保护 Origin；未传 Origin 的 API 客户端不能仅依赖该校验防护，必须继续使用服务器侧 Cookie + CSRF 授权机制。不要在完整测试前启动公网反代。
