## Product and operational boundaries

Linux Panel v0.5 (still being accepted for wider release) is a single-admin, modular Node 24/Fastify + Vue 3 Linux management panel. A shared ActionEngine serves authenticated Web requests and an OAuth PKCE-protected MCP adapter. TOTP is optional. A distinct root-owned systemd update Broker accepts only exact, trusted `origin/main` fast-forward Git commits, builds with the isolated `linuxpanel-updater` account, journals/backs up private state, checks local health and performs constrained rollback/recovery. It is **not** a general root shell, and build-only CI is not a security audit.

Main areas: `apps/api/`, `apps/web/`, `extensions/mcp/`, `core/`, `modules/`, `platform/`, `scripts/`, `deployment/`, `tests/`. Key runbooks: [UPDATER.md](UPDATER.md), [UPGRADING.md](UPGRADING.md), [PRODUCTION-DEPLOYMENT-GATE.md](PRODUCTION-DEPLOYMENT-GATE.md), [UPDATE-ACCEPTANCE.md](UPDATE-ACCEPTANCE.md), [roadmap](roadmap.md).

Production logs at 09:49 UTC showed the bounded Git error from #58, proving that code was active. There is **no evidence yet in this conversation that #59 / `6aa51c9` has been deployed**, and we must not claim it has.
- **Root cause confirmed by owner:** running Git as the dedicated Web service user with `-c safe.directory=/opt/linux-panel` succeeds for both local `rev-parse HEAD` and remote `ls-remote origin refs/heads/main`. The otherwise equivalent `safe.directory=/opt/linux-panel/` (trailing slash, as constructed by the Node server file URL) fails with `fatal: detected dubious ownership`, then causes a misleading origin lookup error. This prompted the #59 path normalization. On the CI Git version the trailing slash was accepted, so the regression validates the **normalized successful path** across versions rather than assuming all versions reject it.
- **Visible behavior:** Web updater controls were restored after #57, and read-only `panel.update.status` returned Broker enabled, `pending:null`, `lastResult:null`. Subsequent `panel.update.check` returned HTTP 502, recorded as a Git discovery error. Other Web API calls and the panel systemd service were observed healthy around that failure. Cloudflare's public 502 response surfaced the upstream error, not evidence that the entire VPS went down.
- **MCP tool exposure:** in the most recent ChatGPT tool inventory on 2026-10-15, **only six tools** were still available: `system_info`, `system_memory`, `system_cpu`, `services_list`, `storage_usage`, `panel_update_request`. **Neither `panel_update_status` nor `panel_update_execute` is verified visible** in that conversation after the #56 code rollout. The old Scope shortage is not supposed to be a blocker on new source, but the client/tool-list refresh versus live `tools/list` has **not** been conclusively diagnosed. Re-check actual server-side `tools/list`, MCP registration/policy and the host connection's refreshed tool listing rather than promising that a UI refresh alone will fix it.
